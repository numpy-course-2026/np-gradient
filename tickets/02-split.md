# GRD-2. Разбиение выборки и батчи

**Автор:** Нина Ковалёва · **Занятие:** 2

Качество модели меряем только на примерах, которых она не видела при обучении. Значит, нужна отложенная тестовая выборка. Разбивать будем **стратифицированно**: доля каждой цифры в тесте та же, что во всём наборе, — иначе на маленьком наборе одна цифра может почти целиком уйти в тест, и точность будет врать.

## Что сделать

Модуль `gradient/split.py`:

- `train_test_split(X, y, test_size=0.2, seed=0)` → `(X_train, X_test, y_train, y_test)`:
  - из каждого класса c, в котором n_c примеров, в тест уходит ровно `floor(n_c * test_size + 0.5)` примеров, какие именно — случайно;
  - обе выборки перемешаны: классы не идут блоками;
  - один и тот же `seed` — одно и то же разбиение; генератор — `np.random.default_rng(seed)`;
  - **без цикла по классам**. Подсказка: `np.lexsort` сортирует по нескольким ключам; если отсортировать по классу, а внутри класса — по случайному числу, останется понять, какой по счёту каждый пример в своём классе.
- `batches(X, y, batch_size, seed=None)` — **генератор** пар `(X_batch, y_batch)`:
  - по `batch_size` строк, последний батч может быть короче;
  - `seed=None` — по порядку, и тогда батч — срез, то есть view, без копирования;
  - иначе — в случайном порядке, одинаковом для одного `seed`; `X` и `y` перемешаны согласованно;
  - один цикл — по батчам — разрешён.

## Критерии готовности

- `make check-grd2` зелёный, GRD-1 не сломан.
- В PR — почему перемешанный батч не может быть view.
