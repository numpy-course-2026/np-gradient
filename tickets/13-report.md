# GRD-13. Отчёт: кривые, матрица ошибок, сравнение оптимизаторов

**Автор:** Нина Ковалёва · **Занятие:** 13

Модель у нас есть, а показать её мы умеем только числом точности в консоли. Для отчёта нужны картинки: кривые обучения (видно, сошлось или нет), матрица ошибок (видно, какие цифры путаются) и честное сравнение оптимизаторов на одинаковых условиях.

Рисуем в файлы, а не в окно: отчёт собирается на сервере, где дисплея нет. Бэкенд `Agg` выбирается **до** импорта `pyplot`.

## Что сделать

`gradient/report.py`:

- `learning_curves(path, histories, title=...)` — потери по эпохам, по линии на каждый ключ словаря `histories`; подписи осей, сетка, легенда. Сохраняет PNG, возвращает путь.
- `confusion_figure(path, cm, title=...)` — матрица ошибок теплокартой с числами в клетках и шкалой цвета. Тоже PNG.
- `compare_optimizers(Xtr, ytr, Xte, yte, sizes=(64, 64, 10), epochs=20, seed=0)` — обучает одинаковые по архитектуре и начальным весам сети тремя оптимизаторами (`SGD(0.5)`, `Momentum(0.1, 0.9)`, `Adam(0.01)`) и возвращает словарь: на каждый оптимизатор — `history` (список `float`), `accuracy`, `seconds` и `confusion` (список списков). Результат должен целиком ложиться в JSON и быть воспроизводимым по `seed`.

Циклы по кривым, клеткам матрицы и оптимизаторам — законны; проверка их разрешает.

## Критерии готовности

- `make check-grd13` зелёный, прошлые тикеты не сломаны.
- В PR — обе картинки (кривые и матрица ошибок для лучшей модели) и таблица сравнения оптимизаторов.
- Там же ответ на вопрос: какие две цифры ваша модель путает чаще всего и почему — посмотрите на сами картинки из `as_images`, а не только на числа.
