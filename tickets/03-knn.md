# GRD-3. Стандартизация, one-hot и первый классификатор

**Автор:** Нина Ковалёва · **Занятие:** 3

Прежде чем писать нейросеть, нужна планка: какую точность даёт самый простой разумный метод? Возьмём k ближайших соседей: чтобы классифицировать картинку, найдём k самых похожих в обучающей выборке и спросим их большинством. Всё, что сделаем дальше, должно быть лучше этого числа.

Заодно подготовим две детали, без которых не обойдётся ни одна модель следующих занятий: стандартизацию признаков и one-hot-кодирование меток.

## Что сделать

`gradient/preprocess.py`:

- класс `Standardizer`:
  - `fit(X)` запоминает `mean_` и `std_` каждого столбца и возвращает `self`;
  - `transform(X)` → `(X - mean_) / std_` по статистикам **обучающей** выборки;
  - `fit_transform(X)`;
  - столбцы, у которых `std_ == 0`, после преобразования равны 0 — без `nan`, `inf` и предупреждений о делении на ноль. В цифрах такие столбцы есть (вы посчитали их в GRD-1).
- `one_hot(y, n_classes=None)` → `float64`, форма `(n, n_classes)`: единица в столбце метки, остальное нули. Без `n_classes` — `y.max() + 1`.

`gradient/knn.py`:

- `knn_predict(X_train, y_train, X_test, k=3)` → метки `int64` для `X_test`:
  - соседи — k ближайших по евклидову расстоянию; при равных расстояниях — тот, что раньше в `X_train`;
  - метка — самая частая среди соседей; при равенстве голосов — меньшая;
  - **посчитайте память.** Разность «все со всеми» через broadcasting для 360 × 1437 картинок по 64 пикселя — это 265 МБ промежуточного массива, а на наборе 28×28 будет десятки гигабайт. Или разбейте тест на куски (один цикл по кускам разрешён), или — лучше — посмотрите задание для синьора занятия 3;
  - голосование — без цикла: `one_hot` соседей и сумма.

`gradient/metrics.py`:

- `accuracy(y_true, y_pred)` → доля совпадений, `float`;
- `confusion_matrix(y_true, y_pred, n_classes)` → `int64` `(n_classes, n_classes)`: элемент `[i, j]` — сколько примеров класса i предсказано как j. Без цикла: подумайте, что делает `np.bincount` с числами `i * n_classes + j`.
